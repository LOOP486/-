# ADR-0004：白盒搭建用布局 DSL 中间表示，模型不直接产出坐标

- 状态：已接受
- 日期：2026-06-10

## 背景

白盒场景搭建是核心场景（用户提供模块化资产，agent 搭建）。让 LLM 直接产出 float transform 错误率极高，且无法校验、无法局部修改。

## 决策

两级中间表示：模型只输出**空间规划层**（格子单位的房间/走廊/楼层/连接关系/功能标注）；确定性的**布局编译器**结合资产 manifest 把规划编译成 `(asset, grid_x, grid_y, floor, rot90)` 放置指令，再换算 world transform 批量 spawn。校验三件套：程序化检查（重叠/封闭/连通）、NavMesh 可达性、截图视觉审查；关卡 metrics 表作为硬约束。

## 备选与取舍

- 模型直出 transform：见背景，否。
- 纯 PCG 程序化生成：可控性差、表达设计意图难；PCG 只用于重复性填充。

## 后果

- 需要设计并维护 DSL schema、布局编译器和 manifest 工具链（Phase 2 主体工作）。
- DSL 覆盖盒子式白盒；异形结构走 `exec_python` 逃生舱。
