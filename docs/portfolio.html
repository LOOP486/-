面向 UE5 开发的AI Agent 工具链

ue5agent 把 C++ 编译闭环、蓝图只读理解、白盒关卡生成、平面图输入和验证证据链组织成一个可扩展的工程代理系统，让工具结果能够被追踪、校验和复盘。

项目解决的不是“让模型懂 UE”，而是让它能在 UE 工程里闭环。

普通 coding agent 在 UE5 场景里常被二进制资产、长验证链路和空间坐标错误卡住。ue5agent 的核心思路是把高层判断留给模型，把坐标、权限、验证和证据交给确定性管线。

01

蓝图与资产不可直接读写

通过编辑器桥导出蓝图 overview、pseudocode、graph 和引用关系，坚持只读理解，不让模型直接编辑节点。

02

编译通过不代表行为正确

把 UBT、PIE、功能测试、输出日志、NavMesh、path_test 和视觉审查都沉淀成结构化证据，作为报告依据。

03

LLM 直接吐坐标风险高

采用布局 DSL、资产清单、白盒编译器、校验器和摆放模板求解器，把白盒结构与陈设变成可回归的程序逻辑。

四层架构：Agent Kernel → MCP 工具层 → UE5 工程 → 知识层。

TaskRunner 处理宏观阶段状态机，AgentLoop 处理步骤内工具调用循环。核心循环只依赖 ChatModel 协议，模型接入通过适配层完成。

01

Agent Kernel

plan → execute → verify → recover → report，包含模型路由、权限、上下文压缩、证据信封和恢复策略。

02

MCP 工具层

挂载外部工具服务，用统一工具注册、参数校验、权限网关和错误回传连接 UE 能力。

03

UE5 工程

编辑器桥、UBT 编译、PIE、功能测试、白盒落地和视口证据都在真实工程里运行。

04

知识层

资产清单、关卡尺度规则、项目文档、ADR、运行日志和评测基线沉淀可复用的领域知识。

用户目标 / 平面图 / 需求文本

输入被规划器转成带工具范围、验收条件和预算的执行步骤。

受限工具面 + 步内循环

每步只暴露需要的工具面，模型在步骤内反复调用工具直到达成契约。

MCP / 本地工具执行

UBT、蓝图只读、白盒构建/校验、本地预览、PIE、path_test 等工具统一回传。

结构化证据与验收器

确定性规则先判，再按需要让模型审查补充；通过后进入报告。

恢复 / 重试 / 回滚

桥接断开、部分副作用、证据缺失等错误会进入不同恢复策略。

核心能力围绕 UE5 真实工作流设计。

这些模块不是单点 demo，而是被执行器、工具权限、证据验收和评测基准串起来的工程能力。

C++

编译闭环

封装 UBT 调用并解析结构化诊断，支持真实 UE 工程编译成功、工具链缺失和注入错误样本。

蓝图

蓝图只读理解

概览、伪代码、节点图和引用查找分层读取蓝图，减少上下文压力和节点编辑风险。

DSL

白盒关卡搭建

LLM 输出拓扑层布局，白盒编译器生成摆放结果，校验器检查重叠、连通、门洞和关卡尺度。

图像

平面图输入 v1

从图片提取墙线，输出 SVG、网格化布局和预览产物，再接入白盒构建与校验。

MCP

工具协议化

MCP 客户端挂载外部工具服务，自带构建、编辑器、白盒和仓库工具等工具面。

视觉

视觉审查

白盒视觉门禁默认走本地预览与视觉审查；缺少这些证据时，不能只凭程序校验收口。

权限

权限与回滚

只读、安全写、工程写、危险操作四级分权；工程写操作走自动快照，白盒批量生成有整批回滚策略。

评测

评测基准

UE 在线评测、SPC/DST 空间评测、陈设评测和离线测试共同覆盖稳定性与回归。
